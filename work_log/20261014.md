## 任务：排查并解决 UniCloud Workspace 云桌面黑屏问题
**时间**：10:15-10:45

### 工作内容
1. **初步排查（误判）**：日志显示连接成功（VM running），窗口 StreamWin 在 -32000,-32000，Vdp 全黑。误判为 Wayland 会话渲染问题，切换 Xorg 后仍黑屏。
2. **深入排查（找到真因）**：
   - VdSession 收到 23MB 视频数据（视频流在传输），但 CPU 仅 3.3%（没解码）。
   - VdSession stderr 出现 **GStreamer 管线崩溃**（`gst_element_unlink: assertion 'GST_IS_ELEMENT (src)' failed` 等）。
   - 系统只装 `gstreamer1.0-plugins-good`，缺 bad/ugly/libav 解码插件，无 avdec_h264/vaapih264dec。
3. **修复**：
   - 安装 `gstreamer1.0-plugins-bad/ugly/libav/vaapi + vainfo`。
   - 删除损坏的 GStreamer 注册表缓存 `~/.cache/gstreamer-1.0/registry.*`。
   - 用干净环境重启客户端 `env -u LD_LIBRARY_PATH ...`。
4. **验证**：VdSession 的 GStreamer-CRITICAL 错误消失；Vdp 窗口截图 `mean 0→0.95`、`颜色 1→106830`，画面正常。截图存 `/home/lsz/桌面/workspace_vdi_fixed.png`。
5. **沉淀**：更新 `online_bug_log.md`（追加最终根因+解决）；新建知识库 `10_系统排障与经验.md`；更新 MEMORY.md、Prompt.md、memory/self_evolution.md。

### 结论
- 黑屏真正根因 = **系统缺少 GStreamer 视频解码插件**，客户端无法解码远程桌面 H.264 视频流。
- 早期"Wayland 渲染失败"是误判（切 Xorg 仍黑屏），已修正。
- 附带发现 DevChat 扩展注入 LD_LIBRARY_PATH（旧 libstdc++）会干扰依赖库加载。
- 保持单屏（IsMultiScreen=false）。

### 经验教训
1. **云桌面黑屏要按"连接→渲染→进程→解码→环境"逐层排除**，先看日志/实测，不凭猜测。Wayland 不是默认根因。
2. **云桌面客户端用 GStreamer 解码，缺解码插件是 Linux 高频黑屏原因**。安装 gstreamer1.0-plugins-bad/ugly/libav 解决。
3. **装了插件但 gst-inspect 找不到** → 删除 `~/.cache/gstreamer-1.0/registry.*` 强制重扫（注册表缓存损坏）。
4. **DevChat 注入 LD_LIBRARY_PATH**（旧 libstdc++）导致 `GLIBCXX_3.4.29 not found`，用 `env -u LD_LIBRARY_PATH` 规避；排查先 `echo $LD_LIBRARY_PATH`。
5. **StreamWin 在 -32000,-32000 是 Qt 离屏渲染窗口的隐藏位置，属正常设计**，勿误判为 bug。
6. **dpkg Installed-Size 单位是 KB**，异常大包用 `du -sk` 实测；单位填错会虚高 1024 倍。
