# 09 工程纪律与设计哲学（Engineering Discipline）

> 本仓库技能背后的工程纪律与设计哲学，来源包括 Ousterhout/Pragmatic Programmer/Kent Beck/Fowler 等经典工程思想。

## 1. TDD（红-绿-重构）

- 技能：`tdd`（model-invoked）。
- 核心：一次一个垂直切片，先写失败测试（红）→ 让测试通过（绿）→ 重构改进设计。
- 反馈速度即速度上限（Pragmatic Programmer）。
- 测试覆盖正反向用例。

## 2. Bug 诊断六阶段（diagnosing-bugs）

技能：`diagnosing-bugs`（model-invoked）。

纪律化诊断循环：
1. **建反馈回路**：让 bug 在受控环境中"变红"（可复现）。
2. **最小化**：缩小到最小复现场景。
3. **假设**：基于证据提出根因假设。
4. **插桩**：加日志/断言验证假设。
5. **修复**：改代码让测试变绿。
6. **回归测试**：确认修复不破坏其他功能。

**关键**：必须先建"能复现 bug 的反馈回路"，再开始假设和修复，否则盲目修。

## 3. 双轴 Code Review（code-review）

技能：`code-review`（model-invoked）。

两轴并行审查，报告分开呈现，不合并排序：

| 轴 | 评审内容 | 典型失败 |
|---|---------|---------|
| **Standards** | 代码是否符合仓库编码标准 + Fowler 坏味道基线 | 功能正确但代码质量差 |
| **Spec** | 代码是否忠实实现需求/规格 | 代码漂亮但功能不对 |

## 4. Fowler 12 种坏味道基线

| 坏味道 | 特征 | 修复 |
|--------|------|------|
| Mysterious Name | 名字不揭示功能 | 重命名 |
| Duplicated Code | 相同逻辑多处 | 提取共享 |
| Feature Envy | 方法更多用其他对象的数据 | 移到它嫉妒的数据上 |
| Data Clumps | 相同字段总一起出现 | 打包成类型 |
| Primitive Obsession | 基本类型代替领域概念 | 给概念自己的类型 |
| Repeated Switches | 相同 switch/if 级联重复 | 多态或共享映射 |
| Shotgun Surgery | 一个变化需散落多处编辑 | 集中到一个模块 |
| Divergent Change | 一个文件因无关原因被改 | 拆分 |
| Speculative Generality | 添加了规格不需要的抽象 | 删除 |
| Message Chains | 长 a.b().c().d() 导航 | 在第一个对象上隐藏 |
| Middle Man | 类主要做委托 | 直接调用真实目标 |
| Refused Bequest | 子类忽略大部分继承内容 | 组合替代继承 |

规则：仓库已有标准 > 坏味道基线；坏味道是判断调用，非硬违规。

## 5. Deep Module 设计（codebase-design）

技能：`codebase-design`（model-invoked）。

- 来源：John Ousterhout《A Philosophy of Software Design》。
- 核心：**deep module** = 大量功能通过小接口暴露，置于干净 seam，可经接口测试。
- 设计过程：先拷问模块边界 → 找 seam → 设计小接口 → 验证可测性。
- `improve-codebase-architecture` 扫描代码库找加深机会。

## 6. 领域建模（domain-modeling）

技能：`domain-modeling`（model-invoked）。

- 主动构建打磨领域模型：挑战术语、边界场景、写 ADR、更新 GLOSSARY.md。
- 与 `grill-with-docs` 配合：拷问会话中同步打磨领域模型。
- 产出：`GLOSSARY.md`（术语表）+ ADR（架构决策记录）。
- 仅"读"不触发，必须"主动构建"。

## 7. 写作规范（writing-for-agents）

技能：`writing-for-agents`（model-invoked）。

为 agent 写文档的纪律：
- **Context Pointer**：指针措辞决定 agent 何时触及材料。
- **信息层次**：步骤内联、参考按需查阅、细枝末节放指针后（渐进披露）。
- **引导词**：用预训练已有的紧凑概念锚定行为。
- **正向引导**：少用否定。
- **单一事实来源**：每个含义只在一个权威位置。
- **每行检查相关性**：删 no-op 指令。

## 8. 原型（prototype）

技能：`prototype`（model-invoked）。

- 构建一次性原型回答设计问题。
- 两种产出：单一 HTML 文件（状态/逻辑问题）或多种 UI 变体（设计问题）。
- 关键：原型是"可丢弃的"，快速回答一个设计问题。

## 9. 常见坑

1. **code-review 双轴漏一轴**：只看功能不看质量（或反之），两轴须并行。
2. **diagnosing-bugs 跳过反馈回路**：直接假设根因，不先建可复现环境。
3. **domain-modeling 只读不写**：仅阅读 GLOSSARY.md 不算建模，须主动挑战/更新。
4. **prototype 被当生产代码**：原型是"可丢弃的"，不应投入生产质量。
